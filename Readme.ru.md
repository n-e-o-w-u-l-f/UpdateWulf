## Краткий обзор

UpdateWulf — служба и инструмент командной строки на Python для небольшой группы доверенных компьютеров. Центральный узел HTTPS получает отчёты об обновлениях; на каждом зарегистрированном компьютере работает фоновый процесс. Интеграция с оболочкой показывает сохранённые результаты, не обращаясь к сети при каждом выводе приглашения.

В публичном исходном коде сейчас указана **версия 2.1.0**. В него входят адаптеры для **APT, pacman, NetBSD pkgin и Windows Update Agent**. Реализация адаптеров и объём проверок на соответствующих платформах различаются; см. [требования](#requirements) и [результаты проверки](docs/documentation-status.md). Семь переводов README **не означают** наличие семи полностью переведённых интерфейсов программы: часть сообщений при работе по-прежнему выводится на немецком.

### Области применения

- Домашняя лаборатория или небольшая группа компьютеров, состояние обновлений которых нужно видеть в одном терминале.
- Компьютеры Linux, Windows и NetBSD с их штатными менеджерами пакетов.
- Сеансы SSH, в которых компактная строка состояния удобнее отдельной панели управления.
- Администраторы, которым важно самостоятельно выбирать время обновлений и сохранять действующие ограничения прав ОС.

UpdateWulf не является системой резервного копирования или универсальной платформой развёртывания ПО. Адаптеры winget, Flatpak, Snap и Homebrew, а также автоматическое управление перезагрузками не реализованы. Синхронизация репозиториев остаётся функцией совместимости с прежними версиями; для новых задач синхронизации Git предназначен GitSyncWulf.

<a id="quick-start"></a>
## Быстрый старт

**Чтобы познакомиться с программой:** нужны Python 3.9+ и Git для показанного ниже клонирования; вместо Git можно сначала скачать и распаковать ZIP-архив исходного кода. Служба и конфигурация не требуются.

```sh
git clone https://github.com/n-e-o-w-u-l-f/UpdateWulf.git
cd UpdateWulf
python3 pc_mesh.py --version
python3 pc_mesh.py --help
```

В Windows замените `python3` на `py -3`, если используется этот способ запуска Python.

**Программа уже установлена, а компьютер зарегистрирован?** Откройте новый терминал:

```sh
updatewulf status
updatewulf status --json
updatewulf diagnose
updatewulf --self update --check
```

`status` читает локальный снимок состояния. `diagnose` проверяет настроенный узел HTTPS. `--self update --check` проверяет публичную ветку приложения без установки. Пустой снимок не доказывает, что все компьютеры обновлены.

<a id="requirements"></a>
## Требования

| Платформа | Среда выполнения и штатный адаптер | Способ установки | Текущие ограничения |
| :--- | :--- | :--- | :--- |
| Debian / Raspberry Pi OS | Python 3.9+, `apt-get` | Пользовательская служба; системная служба systemd | Новые проверки используют отдельный кэш метаданных. |
| Arch Linux | Python 3.9+, `pacman`, `vercmp` | Пользовательская служба; системная служба systemd | Для получения метаданных репозиториев и обновления пакетов нужен доступ к сети. |
| Windows | Python 3.9+ с настоящим `python.exe`; Windows PowerShell и Windows Update Agent | Пользовательское задание планировщика; системные задания с повышенными правами | Адаптера winget нет; в рамках этой работы над документацией проверки непосредственно в Windows не выполнялись. |
| NetBSD | Python 3.9+, `pkgin` | Пользовательский cron как резервный механизм; штатная служба `rc.d` | Проверки без root могут использовать сохранённые метаданные pkgin. |
| Android / Termux | Python 3.9+, APT, фактическая учётная запись Termux | Скрипт запуска Termux при загрузке | Для запуска после перезагрузки нужен Termux:Boot; это не средство обновления ОС Android. |
| Другие платформы | Python может запускать интерфейс командной строки | Полной инструкции по штатной установке нет | Неподдерживаемые средства сбора данных сообщают `UNSUPPORTED`, а не нулевое число обновлений. |

Каждому сетевому фоновому процессу нужны конфигурация регистрации, узел HTTPS, его доверенный сертификат, уникальный токен участника и доступное для записи хранилище состояния. **Для самообновления приложения нужен Git.** Пользовательская установка Unix требует работающего пользовательского менеджера systemd или `crontab`; для `scripts/install.sh` нужен Bash. Необязательные вспомогательные скрипты регистрации прежних версий используют Paramiko; основная служба использует стандартную библиотеку Python.

<a id="installation"></a>
## Установка

### Выберите область установки

| Что вам нужно | Что выбрать | Что изменится |
| :--- | :--- | :--- |
| Команды и строка состояния оболочки для вашей учётной записи | Пользовательская установка | Ваши скрипты запуска, управляемые блоки профилей оболочек и, при необходимости, пользовательский фоновый процесс. |
| Фоновый процесс, запускающийся вместе с компьютером и выполняющий разрешённые обновления ОС | Общесистемная служба | Штатная служба или задание ОС, защищённый вспомогательный компонент обновления пакетов и явно заданная конфигурация владельца. |
| Только ознакомиться с инструментом | Копия исходного кода | Запуск `pc_mesh.py --help` / `--version`; установка не нужна. |

**Сначала настройте регистрацию:** следуйте инструкции [по настройке центрального узла и участников](docs/configuration.md#first-setup). Файлы в [examples/](examples/) содержат заполнители, а не действующие учётные данные. Храните заполненную конфигурацию вне дерева исходного кода, обычно в `~/.config/pc-mesh/config.json` (`%USERPROFILE%\.config\pc-mesh\config.json` в Windows). Разместите скачанную программу в постоянном каталоге: установщики ссылаются на него.

### Установка для текущего пользователя

Запускайте команды из каталога скачанного исходного кода под учётной записью, которая будет использовать UpdateWulf:

```sh
# Unix: установить скрипты запуска, интеграцию с оболочкой и постоянный пользовательский процесс.
python3 install.py
```

```powershell
# Windows PowerShell: используйте настоящий исполняемый файл Python, а не псевдоним Microsoft Store.
$Python = (Get-Command python.exe -ErrorAction Stop).Source
& $Python -c "import sys; assert sys.version_info >= (3, 9)"
.\install_windows.ps1 -Python $Python
```

Только для интеграции с оболочкой используйте `python3 install.py --prompt-only` или `.\install_windows.ps1 -Python $Python -PromptOnly`. В этом режиме новые данные не собираются: нужен кэш уже работающего фонового процесса. В Termux запускайте `python install_termux.py` непосредственно в сеансе Termux. Обновление приложения в Termux пока требует ручной замены через его собственный установщик; сохраняйте `auto_self_update: false`, поскольку общий механизм не обновляет скрипт автозапуска Termux.

Откройте новый терминал и выполните `updatewulf --version`, `updatewulf diagnose` и `updatewulf status`. [Руководство по установке](docs/installation.md) объясняет расположение файлов, запуск, проверку и откат.

### Общесистемная установка

Общесистемная установка означает штатный фоновый процесс машины и контролируемые права на обновление пакетов; она не настраивает автоматически оболочку каждого пользователя. Сначала подготовьте отдельную учётную запись службы и её конфигурацию регистрации. Используйте постоянный каталог исходного кода под контролем администратора и следуйте процедуре переключения для своей платформы:

- [Linux / systemd](docs/installation.md#linux-systemwide): `enable_machine_updates.py --user … --config … --state … --source …`, из действительного сеанса root.
- [Windows](docs/installation.md#windows-systemwide): `enable_machine_updates_windows.ps1 -Python … -Config … -Owner …`, из консоли владельца с повышенными правами.
- [NetBSD](docs/installation.md#netbsd-systemwide): `enable_machine_updates_netbsd.py --config … --state … --python …`, из действительного сеанса root.

Эти установщики не повышают свои права самостоятельно. Установка под управлением системной службы использует штатную процедуру переключения выпуска, а не пользовательский установщик самообновления.

## Примеры повседневного использования

Замените `workstation.local` именем компьютера из отчёта или регистрации либо используйте точный идентификатор участника. Поддерживаются оба порядка: сначала компьютер или сначала действие.

| Цель | Команда | Результат |
| :--- | :--- | :--- |
| Прочитать сохранённое состояние всех компьютеров | `updatewulf status` | Локальное чтение. |
| Посмотреть один компьютер | `updatewulf workstation.local status` | Локальный снимок с фильтром. |
| Экспортировать состояние | `updatewulf status --json` | Исходный снимок, включая временные метки. |
| Отключить цвета командной строки | `updatewulf status --no-color` | Обычный текст. |
| Проверить подключение | `updatewulf diagnose` | Аутентифицированный `GET /fleet`; задание обновления не создаётся. |
| Запросить новую проверку обновлений | `updatewulf workstation.local refresh --wait 60` | Ставит проверку в очередь и ждёт до 60 секунд. |
| Установить обновления пакетов ОС | `updatewulf workstation.local update --wait 600` | Явный запрос штатного обновления; нужны регистрация и права на целевом компьютере. |
| Поставить в очередь без ожидания | `updatewulf workstation.local update --wait 0` | Выводит поставленное в очередь задание; это не подтверждение завершения. |
| Открыть меню | `updatewulf tui` | Интерактивное меню оператора; см. известную проблему с пустым списком компьютеров. |
| Проверить само приложение UpdateWulf | `updatewulf --self update --check` | Проверяет публичную ветку приложения. |
| Обновить само приложение UpdateWulf | `updatewulf --self update` | Подготавливает, проверяет и активирует исходный код приложения для поддерживаемой пользовательской установки. |

`updatewulf all update` запрашивает обновление **всех зарегистрированных целевых компьютеров**. Используйте эту команду только тогда, когда именно это и требуется. Истечение времени ожидания CLI не отменяет уже работающий менеджер пакетов. Полный справочник действий, параметров и кодов возврата находится в [руководстве](docs/manual.md).

## Конфигурация

Конфигурация хранится в JSON. Начните с примера [клиента](examples/config.client.json), [центрального узла](examples/config.hub.json) или [оператора](examples/control.json), затем следуйте [полному справочнику конфигурации](docs/configuration.md). Пути в JSON воспринимаются буквально: указывайте абсолютные пути; `~` и переменные окружения обычно не раскрываются внутри строк JSON.

| Параметр | Значение по умолчанию в коде | Назначение |
| :--- | :--- | :--- |
| `scan_interval` | `1800` секунд | Интервал между проверками пакетов. |
| `report_interval` | `20` секунд | Интервал отправки отчётов центральному узлу. |
| `auto_self_update` | `true` | Включает обновление приложения, если режим фонового процесса это допускает. |
| `self_update_interval` | `21600` секунд | Интервал проверки приложения; ограничен диапазоном 1–24 часа, первая проверка — после ожидания 5 минут. |
| `self_update_branch` | `main` | Публичная ветка приложения. |
| `announce_only` | `false` | Отключает прежние функции Git; при `machine_control: false` также отключает обработчик запросов. |
| `machine_control` | `false` | Разрешает запросы проверки и установки в режиме announce-only. |
| `native_installer` | `false` | Направляет установку через заранее подготовленный штатный вспомогательный компонент. |

В примерах намеренно задано `auto_self_update: false`, чтобы первая настройка была предсказуемой. Включайте эту функцию после проверки пользовательской установки из публичного репозитория. Для команд оператора файл `control.json` в стандартном каталоге имеет приоритет над `config.json`; явно заданный нестандартный `--config` выбирает указанный файл. Ограничения самообновления при нестандартных путях конфигурации и состояния описаны в [известных проблемах](docs/troubleshooting.md#known-issues).

## Службы, состояние и самообновление

Пользовательская служба называется `updatewulf.service` в systemd или `UpdateWulf-User` в планировщике заданий Windows. Имена системных служб различаются; они перечислены в [руководстве по установке](docs/installation.md). Журналы и снимки обычно находятся в `~/.local/state/pc-mesh/`, включая `service.log`, `heartbeat.json`, `fleet.json` и `executed-commands.json`.

Возможные состояния: `OK`, `CACHED`, `CHECKING`, `UNKNOWN`, `ERROR` и `UNSUPPORTED`. Сохранённые данные, в том числе данные недоступных компьютеров, остаются видимыми и не выдаются за новую успешную проверку. У заданий собственные состояния, включая `QUEUED`, `RUNNING`, `SUCCEEDED`, `FAILED`, `NEEDS_ADMIN`, `EXPIRED` и `INTERRUPTED`.

Самообновление проверяет идентичность репозитория, целостность объектов Git и отношение коммитов в истории, выполняет проверки подготовленного кода и сохраняет текущий и предыдущий выпуски. Проверки Git не являются проверкой цифровой подписи выпуска. Первый переход требует явной команды оператора. Действующая конфигурация и данные регистрации находятся вне каталога выпуска. Откат и осторожные ограничения очистки описаны в [руководстве](docs/manual.md#application-self-update).

## Известные проблемы и устранение неполадок

В [руководстве по проблемам](docs/troubleshooting.md#known-issues) перечислены конкретные ограничения и обходные решения. Сейчас:

- Полного межплатформенного деинсталлятора нет; следуйте [процедуре ручного удаления](docs/installation.md#uninstall).
- Пользовательское самообновление не всегда сохраняет нестандартные пути состояния и конфигурации Unix; используйте стандартные пути или ручное переключение штатными средствами.
- TUI может завершиться с ошибкой при навигации по пустому списку компьютеров; до регистрации участника используйте `status` и `diagnose`.
- Интеграция с приглашением Bash не полностью учитывает `NO_COLOR`; для гарантированно бесцветного вывода CLI используйте `status --no-color`.
- Неизвестное содержимое выпуска, включая дополнительные каталоги документации, из предосторожности блокирует автоматическое удаление старого выпуска.
- Адаптеры macOS/Homebrew, winget, Flatpak и Snap, а также полный перевод сообщений программы не реализованы.

Если команда не найдена, откройте новую оболочку и проверьте пользовательский каталог исполняемых файлов. При `NEEDS_ADMIN` проверьте штатный вспомогательный компонент и разрешение `allow_install` участника. При ошибках TLS или аутентификации проверьте сертификат, имя компьютера и регистрацию. Не подменяйте неудавшуюся проверку предполагаемым нулём обновлений.
